# 技术路线图的逻辑构建与可视化

技术路线图（Technical Route）是申报书的“骨架”，评审专家通常会通过这张图快速判断项目的逻辑是否通顺、方案是否可行。

## 1. 核心逻辑结构

一张优秀的技术路线图应包含以下四个层次：

1. **输入层 (Input)**：研究背景、科学问题、研究目标。
2. **执行层 (Execution)**：具体的研究内容（模块 1, 模块 2, 模块 3）。
3. **关联层 (Relation)**：各模块之间的逻辑递进、反馈或支撑关系。
4. **输出层 (Output)**：预期成果、科学结论、目标达成。

## 2. 逻辑流向设计

- **串联式**：模块 A 是模块 B 的前提。
- **并联式**：多个模块共同支撑核心目标的达成。
- **反馈式**：模块 C 的结果可能返回修改模块 A 的参数（常见于模型优化）。

## 3. 可视化建议 (Draw.io 整合)

建议使用 Draw.io 或类似工具绘制，遵循以下原则：
- **配色**：使用淡雅的学术色调（如浅蓝、浅灰、淡绿），避免高饱和度颜色。
- **字体**：中文使用宋体/微软雅黑，英文使用 Arial/Times New Roman。
- **箭头**：实线表示直接流向，虚线表示反馈或参考。
- **关键节点**：用加粗框或不同颜色突出“关键科学问题”或“核心算法”。

## 4. 常见逻辑硬伤
- **孤岛模块**：某个研究内容在图中没有输入也没有输出。
- **逻辑断层**：从研究内容直接跳到研究目标，中间缺乏关键的验证环节。
- **过于复杂**：连线像蜘蛛网，让专家看不出主线。

## 5. 文字配合
在图下方应有简短的文字说明（300-500字），概括技术路线的逻辑思路。
> “本项目拟采用...的总体思路，首先通过...获取...，进而利用...构建...，最后通过...验证...。”
