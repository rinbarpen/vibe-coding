# 中国专利说明书撰写规则

> 本文件是撰写中国专利说明书的权威编写规则。各子技能（writer、review）必须遵守。详细参考见 [../reference.md](../reference.md)。

## 一、说明书结构（必须齐全，顺序不可变）

1. **技术领域** — 发明所属技术领域，简明说明涉及范围
2. **背景技术** — 现有技术现状及存在的问题、不足
3. **发明内容** — 要解决的技术问题、技术方案、有益效果
4. **附图说明** — 各附图的简要说明，与图片一一对应
5. **具体实施方式** — 结合附图对技术方案的具体描述

可选但建议包含：
6. **权利要求书**（`<section id="claims">`）
7. **摘要**（`<section id="abstract">`）

## 二、各章节撰写要点

### 技术领域
- 简明说明发明所属技术领域，不写广告语
- 常见表述：「本发明涉及……」「本申请涉及……」
- 避免：过于宽泛（如「涉及机械领域」）或混入发明内容

### 背景技术
- 介绍与本发明最接近的现有技术，指出现有方案的不足或待解决问题
- 可引用现有专利或公知技术，客观描述，不贬低他人
- 常见问题：与发明内容重复、缺少对现有缺陷的明确指认

### 发明内容
- **要解决的技术问题**：针对背景技术中的不足，明确本发明要解决的问题
- **技术方案**：概括解决该问题所采用的技术手段，与独立权利要求的表述对应
- **有益效果**：相对现有技术带来的效果（性能、成本、可靠性等）

### 附图说明
- 对各附图逐一简要说明，如「图1是……结构示意图」「图2是……流程图」
- 附图编号与正文引用、图片文件名一致（图1、图2……）
- 仅说明是什么图，不在此展开技术细节

### 具体实施方式
- 结合附图详细描述技术方案的实施方式，使本领域技术人员能够实现
- 对附图标记（零件编号）在正文中应有对应说明
- 可给出多个实施例或变形例以支持权利要求范围
- 常见问题：只有概括无具体结构/步骤；附图与文字不对应

### 权利要求书
- **独立权利要求**：限定完整技术方案，包含必要技术特征
- **从属权利要求**：引用在先权利要求，进一步限定附加技术特征
- 用语与说明书一致，避免出现说明书中未出现的术语

### 摘要
- 概括发明要点，一般 300 字以内
- 可配一幅代表性附图（摘要附图）

## 三、用语规范

- 统一使用「本发明」或「本申请」；同一篇内不要混用
- 数字、单位、符号与国家标准或行业习惯一致
- 避免商业性、宣传性用语（如「领先」「最佳」）
- 关键术语必须在说明书与权利要求书中保持一致

## 四、HTML 格式规范（用于 docx 导出）

### 标签
- 使用语义化标签：`<h1>`~`<h3>`、`<p>`、`<ul>`/`<ol>`
- DOCTYPE：`<!DOCTYPE html>`，语言声明：`<html lang="zh-CN">`

### 表格
- 使用 `<table class="patent-table" border="1">`
- 表名/标题位于表格上方，使用四号黑体
- 表内文字使用五号或小五宋体
- 边框使用实线边框

### 图片
- 必须使用本地路径（如 `images/图1.png`），严禁使用 HTTP URL
- 图注使用 `<figure><img ... /><figcaption>图1 xxx</figcaption></figure>`
- 图注放在图片下方，图号（图1、图2）写在 HTML 文档中，严禁包含在图片像素内

### 数学表达
- 行内公式：`\(...\)`
- 行间公式：`$$...$$`
- 导出 docx 时通过 `scripts/html_to_docx.py` 自动转换为 Word 公式对象

### 文字格式
- 字体：宋体 (SimSun)
- 字号：小四 (12pt)，标题可用四号 (14pt) 或三号加粗
- 行间距：1.5 倍行距
- 段落首行缩进 2 字符
- 颜色：纯黑色
- 页边距：左边和上边各 25mm，右边和下边各 15mm
