# 技术评估框架

## 目的

在一个行业中，理解技术现状和趋势，判断技术对行业格局的影响。

## 分析维度

```
技术定义 → 成熟度 → 竞争格局 → 影响评估 → 趋势判断
   ↓         ↓         ↓          ↓          ↓
 什么技术？ 到什么    谁在做？   如何影响    下一步？
 如何工作？ 阶段了？  谁领先？   行业结构？  何时发生？
```

## 1. 技术成熟度

### Gartner Hype Cycle 技术成熟度曲线

```
期望值
   ↑
   │          ┌─── 期望膨胀顶峰 (Peak of Inflated Expectations)
   │         ╱│╲
   │        ╱ │ ╲
   │       ╱  │  ╲
   │ 技术触发 ─┘   ╲  ─── 泡沫破灭低谷 (Trough of Disillusionment)
   │ (Tech         ╲╱
   │  Trigger)      ╲
   │                ┌────── 稳步增长 (Plateau of Productivity)
   │               ╱
   │    启蒙斜坡 (Slope of Enlightenment)
   └──────────────────────────────────────────→ 时间
```

| 阶段 | 特征 | 投资判断 |
|:----:|------|---------|
| **技术触发** | 首个概念验证，媒体关注 | 高风险，适合研究 |
| **期望顶峰** | 过热，过度承诺 | 泡沫风险，谨慎 |
| **泡沫破灭** | 失望，整合 | 真正价值开始显现 |
| **启蒙斜坡** | 最佳实践形成 | 进入好时机 |
| **稳步增长** | 主流采用开始 | 市场竞争激烈 |

### TRL (Technology Readiness Level)

| 等级 | 说明 | 对应阶段 |
|:----:|------|:--------:|
| TRL 1-3 | 基础研究到概念验证 | Hype Cycle 早期 |
| TRL 4-5 | 实验室验证到模拟环境 | 触发-期望顶峰 |
| TRL 6-7 | 真实环境原型验证 | 泡沫破灭-启蒙 |
| TRL 8-9 | 系统完成到实际部署 | 稳步增长 |

## 2. 技术路线图 (Technology Roadmap)

### 绘制方法

```
当前          短期(1-2年)    中期(3-5年)    长期(5年+)
─────────     ─────────    ──────────    ─────────
 技术A        技术A优化     技术B商用     技术C突破
 (v1.0)       (v2.0)        (首批产品)    (原型)
                │               ↑
 并行技术X ◄────┘               │
 (实验室)                       │
                    突破性技术Y ◄┘
                    (研发中)
```

### 竞争性技术路线分析

| 技术路线 | 支持者 | 优势 | 劣势 |
|---------|--------|------|------|
| 方案A | 大公司群 | 成熟、兼容 | 天花板明显 |
| 方案B | 创业公司 | 颠覆性、效率高 | 生态不成熟 |
| 方案C | 学术界 | 理论上最优 | 离商用远 |

## 3. 专利分析

### 关键指标

| 指标 | 含义 |
|------|------|
| 专利申请量年增长 | 技术关注度变化 |
| 专利授权率 | 技术质量 |
| 被引次数 | 核心技术识别 |
| 主要专利权人 | 竞争格局 |
| IPC分类分布 | 技术领域覆盖 |

### 判断框架

```markdown
专利增速 > 20% = 技术活跃期
专利增速 < 5%  = 技术成熟期
龙头企业专利集中度 > 50% = 技术壁垒高
新兴企业专利占比上升 = 竞争格局可能变化
```

## 4. 颠覆性技术判断

### Christensen 颠覆性创新框架

| 类型 | 说明 | 案例 |
|:----:|------|------|
| **低端颠覆** | 从被忽视的低端市场切入，逐步上攻 | 丰田→豪华车，Linux→服务器 |
| **新市场颠覆** | 创造新市场或新用户群 | 智能手机、共享出行 |

### 颠覆性技术的信号

- ✅ 性能在主流标准上不如现有方案，但在某些方面有独特优势
- ✅ 价格显著更低，吸引"非消费者"
- ✅ 现有龙头企业忽视或嘲笑该技术
- ✅ 技术在快速迭代中性能迅速提升
- ✅ 市场从"足够好"的客户群开始接受

## 5. 技术影响评估

### 对行业结构的影响

```markdown
| 影响维度 | 评估 |
|----------|------|
| 降低进入壁垒? | 是/否，如何降低 |
| 改变价值链? | 是否消除中间环节或创造新环节 |
| 影响供需关系? | 供给侧效率提升 / 需求侧创造新需求 |
| 改变竞争基础? | 从成本竞争转向技术竞争 |
```

### 技术采用生命周期 (Technology Adoption Lifecycle)

```
创新者   早期采用者  早期多数   后发多数   落后者
  2.5%     13.5%     34%       34%      16%
  ┌──┐   ┌────┐   ┌──────┐  ┌──────┐  ┌────┐
  │  │   │    │   │      │  │      │  │    │
  └──┘   └────┘   └──────┘  └──────┘  └────┘
   ↑       ↑          ↑
  "鸿沟" (The Chasm)
  早期市场 ←→ 主流市场
```

> 关键洞察：**跨越鸿沟**（Crossing the Chasm）是从早期采用者到早期多数之间的关键转折点。做不到→技术停留在小众；做到→进入主流市场。

## 分析步骤总结

```
1. 识别关键技术
   - 这个行业依赖哪些技术？哪些是新出现的技术？

2. 评估成熟度
   - 每种技术在 hype cycle 和 TRL 的什么位置？
   - 技术路线是否趋于收敛或多路线并行？

3. 对比竞争性技术
   - 不同技术路线的支持者、优势、劣势？
   - 专利数据说明了什么？

4. 判断颠覆潜力
   - 是否存在颠覆性技术？信号是什么？

5. 预测行业影响
   - 技术会改变行业结构吗？会改变竞争基础吗？
   - 会在什么时间范围内产生影响？
```
